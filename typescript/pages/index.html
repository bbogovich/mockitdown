The mockitdown gallery

The pack gallery shows every shipped pack: each element the pack offers, with its role, arguments, defaults and variants, and complete design examples in the pack's style, from a sign-in form to a mail client. It is where packs are reviewed by eye, and it is the end-to-end test page of the TypeScript variant: the browser tests open it, render every pack and fail on any diagnostic.

Open the pack gallery

Rendered in your browser

Every mockup in the gallery is rendered in the browser by the TypeScript renderer, through the mockitdown-mockup web component: the page holds mockitdown source, and the component turns it into HTML in its shadow root. Markdown sites (MkDocs, Zensical) use the Python package instead: pip install mockitdown, whose Markdown extension renders mockitdown fences at build time, with the same output.

Using the TypeScript library

Download the archive attached to a GitHub release and serve its dist/ folder with your page. Load the shared assets (packs, stylesheets, icons) once with loadAssetsFromUrl, then write each mockup as a <mockitdown-mockup> element holding a <script type="text/mockitdown">:

<script type="module">
  import { loadAssetsFromUrl } from "./mockitdown/dist/mockitdown.js";
  await loadAssetsFromUrl();   // the package's own dist/shared/
</script>

<mockitdown-mockup pack="fluent" device="fit">
  <script type="text/mockitdown">
    VStack {
      Text("Hello").font(.title)
      Button("Continue") {}
    }
  </script>
</mockitdown-mockup>

The attributes are those of the Markdown fence (pack, device, appearance, chrome, …). The TypeScript README covers the API, Node use and development.
