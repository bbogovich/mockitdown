What: split typescript/src/core/render/html.ts (2265 lines) mirroring the Python split, with the same module names. The Renderer class (infrastructure, shared helpers, option/field/calendar/rows helpers) stays in html.ts; the ROLES record is assembled by object spread from per-family objects in typescript/src/core/render/roles/ (layout.ts, content.ts, controls.ts, navigation.ts, containers.ts, components.ts, annotations.ts), each exporting a Record<string, RoleFn>. Module constants and helpers (PASSTHROUGH, PICKER_*, DATE_STYLES, GAUGE_ARC, has/at/raw/stripTags/entries, date helpers) go where they are used or into the existing util.ts. Exports of core/render/index.ts unchanged.

Why: same as the Python split. #23 and the design-tool work touch every role in both variants, and the renderers are line-for-line mirrors, so identical module names keep Python and TS diffs reviewable side by side. Pure move: output stays byte-identical to the Python renderer.

Files: typescript/src/core/render/html.ts, new typescript/src/core/render/roles/*.ts, util.ts if shared helpers move, index.ts (imports only).

Guard tests (unchanged, must pass): npm test (tests/unit: render.test.ts, conformance.test.ts, patterns.test.ts, packs.test.ts, gallery.test.ts, elements.test.ts); browser specs core.spec.mjs and mockup.spec.mjs; npm run build succeeds with no material bundle growth. Update A-REND-1 and A-WEB-1 pages; commit with sio commit --refactor.
