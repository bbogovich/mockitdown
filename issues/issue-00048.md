What: split python/src/mockitdown/render/html.py (2565 lines) into role-family modules. The Renderer class keeps infrastructure and shared helpers (view, open, icon, content, slot, decorations, overlays, option/field/calendar helpers) in html.py; the r_<role> methods move into mixin classes in python/src/mockitdown/render/roles/ (layout, content, controls, navigation, containers, components, annotations: the seven sections html.py already marks with "# ---" comments) and Renderer inherits them. Module-level helpers (_parse_date, _parse_time, _format_date, _decorate, _col_name/_col_index/_parse_range, _hour, _highlight, _terminal_line, _cursor_svg) move next to the one family that uses them, or to render/_util.py when shared. html.py keeps exporting Renderer, esc, _bool, _name (render/__init__.py imports them) and the constants other modules use.

Why: the queue (#23 edit-mode render option, #20-#46) adds data-mkd-node and derived marks to every role in both renderers; one 2.5k-line class makes each such change a merge hotspot and hard to review. Seven files of 150-500 lines keep edits local. Pure move: no markup, diagnostics, attribute order or API change; dispatch stays getattr(self, "r_"+role).

Files: python/src/mockitdown/render/html.py, new python/src/mockitdown/render/roles/*.py, render/__init__.py (imports only if needed).

Guard tests (unchanged, must pass): python/tests test_render.py, test_samples.py, test_conformance.py, test_patterns.py, test_fit.py, test_layout.py, test_menubar.py, test_shapes_charts.py, test_swiftui_*.py, test_examples.py; python tools/gen_reference.py must leave shared/reference byte-identical (git diff clean). Update A-REND-1 and the implementation page to name the new modules; commit with sio commit --refactor.
