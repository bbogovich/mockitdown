## Prompt (SRC-19#request)

> The "Demo" page in the doc site should be "user guide".  It needs an installation page with instructions for the python and typescript versions, and how to build a resulting page with embedded mockups (mainly for python).  Some things in the current doc are referenced but not defined.  The use of import paths, for example, gives no indication of where the import_paths are defined.  Using a custom component loaded from another file is described, but not how to reference a component defined in the same page.  For import_paths, it makes sense that this be a "virtual file system" definition mapping a URL to the namespace paths used in the actual imports (like typescript config).  For custom components, they should be optionally usable as templates where a design importing the control can override propoperty values and embed content within the layout.  The "@ContentBuilder" parameter attribute appears to be the correct way to handle this in SwiftUI. We need to allow for multiple libraries of custom views to have overlapping view names, so the library name prefix needs to be supported in imports.

Answers in conversation (SRC-19#answers): named library blocks `import "#name"`; `Library.Name` qualification; `import_paths` replaced, not kept.

## This issue

Replace `import_paths` with the import map `imports` in both variants: the Markdown extension option (default `{"": "docs"}`, `import_paths` a configuration error with the migration message), the render option and `RenderOptions` field (M-OPT-1.F15), the CLI `-I KEY=TARGET`, `./`-only relative resolution against the importing file, longest-key matching without fallback, list targets, `http(s)`/`file:` targets (Python: `urllib.request`, stdlib only — no new dependency), and in the TypeScript core and elements `imports`, `<script type="mockitdown-imports">`, the `imports` attribute and `import-base` as the base of relative targets.

Migrate every configuration in the same commit: `python/examples/site/mkdocs.yml` (`imports: {"": docs/mockups}`), `python/tools/`, tests and fixtures, the TypeScript pages, and — in the docs worktree — `site.yml` (`imports: {"": docs/specification/mockups}`), so the docs site still builds with the new code. The example site docs pages that say `import_paths` are rewritten by the User guide issue; here only make them build.
